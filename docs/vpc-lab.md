# VPC 구성 관계와 검증 기준

[저장소 소개](../README.md)

아래 CIDR은 구성 관계를 설명하기 위한 **사설 주소 예시**입니다. 실제 AWS 계정의 VPC ID, 접속 주소 또는 실행 결과가 아닙니다.

| 위치 | 예시 CIDR | 경로와 역할 |
|---|---|---|
| VPC | `10.20.0.0/16` | 두 서브넷을 포함하는 주소 공간 |
| 공개 서브넷 | `10.20.0.0/24` | `0.0.0.0/0 → 인터넷 게이트웨이`; 공개 EC2와 공개 NAT 게이트웨이 |
| 비공개 서브넷 | `10.20.1.0/24` | `0.0.0.0/0 → NAT 게이트웨이`; 공인 IPv4 없는 EC2 |

서브넷이 서로 다른 가용 영역에 있고 공개 NAT 게이트웨이가 한 영역에만 있다면, NAT가 속한 영역의 장애는 다른 영역의 비공개 서브넷 외부 연결에도 영향을 줄 수 있습니다. 이는 단일 NAT의 가용성 경계이며 다중 가용 영역 복원력을 검증한 구성이 아닙니다.

## 구성 순서와 확인할 항목

| 순서 | 구성 작업 | 확인할 항목 |
|---|---|---|
| 1 | VPC와 공개·비공개 서브넷 생성 | CIDR 중복 여부와 가용 영역 |
| 2 | 인터넷 게이트웨이를 VPC에 연결하고 공개 경로 지정 | 라우팅 테이블의 기본 경로와 서브넷 연결 |
| 3 | 공개 EC2에 필요한 웹 서비스 준비 | 공인 IPv4, 보안 그룹 출처·포트, 인스턴스와 HTTP 응답 |
| 4 | 공개 NAT 게이트웨이를 공개 서브넷에 두고 비공개 경로 지정 | NAT 상태·탄력적 IP와 비공개 기본 경로 |
| 5 | 공인 IPv4 없는 비공개 EC2 시작 | 주소, 허가된 관리 경로, 외부 연결 결과 |
| 6 | 시험 후 리소스 정리 | EC2, NAT·탄력적 IP, 라우팅·게이트웨이·VPC 종속성 |

공개 서브넷의 이름이나 기본 경로 하나만으로 인터넷 접근이 보장되지는 않습니다. 공인 IPv4, 보안 그룹, 네트워크 ACL, OS 방화벽과 실제 서비스 응답을 각각 확인합니다. 보안 그룹은 필요한 프로토콜과 접속 출처로 제한하며 암호 기반 SSH를 기본 접근 방식으로 전제하지 않습니다.

이 표는 **수행할 검사 항목**입니다. 실제 검증 결과를 남기려면 시점·리전·익명화한 구성, 요청과 응답, 리소스 정리 상태를 기록해야 합니다. NAT·탄력적 IP·EC2는 비용이 발생할 수 있으므로 생성 전에 현재 요금과 할당 상태를 확인합니다.

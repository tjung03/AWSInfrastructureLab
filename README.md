# AWS VPC 네트워킹 실습 기록

개인 AWS 과정 노트의 모듈 03·04에서 다룬 **사용자 정의 VPC, 공개·비공개 서브넷, 라우팅, 인터넷 게이트웨이, NAT 게이트웨이와 EC2**의 관계를 정리했습니다. 콘솔 중심 실습을 다시 확인할 수 있도록 구성과 점검 항목을 문서화한 저장소입니다. 배포 템플릿이나 현재 실행 중인 AWS 환경은 포함하지 않습니다.

## 실습 구성

| 구성 요소 | 노트에 적힌 역할과 연결 |
|---|---|
| VPC | `10.3.0.0/16` 범위의 사용자 정의 네트워크 |
| 공개 서브넷 | `10.3.0.0/24`, 공개 라우팅 테이블의 인터넷 방향 `0.0.0.0/0 → 인터넷 게이트웨이` |
| 비공개 서브넷 | `10.3.1.0/24`, 비공개 라우팅 테이블의 인터넷 방향 `0.0.0.0/0 → 공개 서브넷의 NAT 게이트웨이` |
| EC2 | 공개 서브넷의 웹 인스턴스와 공인 IPv4가 없는 비공개 인스턴스를 구분 |

공개 인스턴스의 인터넷 통신에는 게이트웨이 경로와 공인 IPv4 주소, 허용된 보안 그룹 규칙이 각각 필요합니다. 비공개 인스턴스는 기록된 구성에서 NAT를 통해 외부로 나가며, NAT만으로 외부에서 해당 인스턴스로 직접 접속할 수는 없습니다. [구성 및 점검](docs/vpc-lab.md)에 노트의 작업 순서와 확인할 지점을 함께 정리했습니다.

## 무엇을 확인할 수 있나

1. 공개 서브넷과 비공개 서브넷의 라우팅 테이블을 비교합니다.
2. 공개 EC2에는 공인 IPv4 할당과 필요한 인바운드 규칙을, 비공개 EC2에는 공인 IPv4 미할당을 확인합니다.
3. 비공개 인스턴스의 외부 통신을 확인할 때 NAT와 공개 서브넷의 인터넷 게이트웨이 경로를 함께 점검합니다.
4. 리소스를 정리할 때 EC2, NAT 게이트웨이와 탄력적 IP, VPC 관련 구성의 의존성을 확인합니다.

노트에는 이 설정 절차와 테스트 항목이 있지만 성공 결과 로그·설정 내보내기·현재 계정 검증은 없습니다. 이 문서의 점검 목록은 **재실습 시 확인할 기준**이며 완료 증거가 아닙니다. 공개·비공개 서브넷을 각 하나 더 추가하는 기록도 있으나, 처음의 단일 NAT 구성을 전체 가용 영역에 대한 장애 대응 구조라고 주장하지 않습니다. 모듈 05 이후의 스토리지·데이터베이스·자동 확장·CloudFormation 등은 이 저장소의 구현 범위가 아닙니다.

## 현재 문서와의 관계

이 저장소는 당시의 *가용 영역에 생성한 공개 NAT 게이트웨이* 흐름을 설명합니다. AWS는 현재 [인터넷 게이트웨이 구성](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html), [NAT 게이트웨이 기본 사항](https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-basics.html)과 [Regional NAT 게이트웨이](https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateways-regional.html)를 각각 문서화하고 있습니다. 실제 재구성 시 서비스 옵션, 요금, 가용 영역별 복원력과 접근 제어를 현재 계정과 요구 조건에 맞게 다시 결정해야 합니다.

노트에 기록된 실제 AWS 리소스 ID, 공인 IP, 계정 정보, 접속 암호와 광범위한 인바운드 허용값은 공개하지 않았습니다. 이 저장소는 AWS 리소스를 자동 생성하는 명령이나 자격 증명을 제공하지 않습니다.
